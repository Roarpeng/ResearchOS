# UX 原则：流式步骤、引用与人工中断

ResearchOS 前端的核心体验是 **「看得见的研究过程」**：用户能理解 Agent 在做什么、依据是什么、何时需要自己拍板。本章约束流式步骤、引用展示与人工中断三类交互。

## 1. 总原则

1. **过程优先于答案**：在终稿出现前，主区域应持续反映当前阶段与步骤，而不是空白等待。
2. **一条主时间线**：步骤、工具、消息增量挂在同一任务时间线上，避免多块仪表盘抢注意力。
3. **引用可追溯**：任何关键结论应能点到来源片段；无引用的强断言要 visually 降权或由 Reviewer 拦截。
4. **中断是一等公民**：暂停等待人类时，UI 必须明确阻塞原因与可选动作，禁止静默挂起。
5. **可恢复**：刷新或断线后，依据 `last_seq` 重放，用户不丢失上下文。
6. **少而准的动效**：用 2–3 种有意义的运动表达「进行中 / 新引用 / 需要决策」，避免装饰性噪声。

## 2. 流式步骤（Streaming Steps）

### 用户应看到什么

| 元素 | 说明 |
|------|------|
| 阶段徽章 | `queued` → `planning` → `researching` → `reviewing` → `writing` → `completed` |
| 计划列表 | 来自 `plan.updated`；当前步高亮 |
| 步骤卡片（非营销卡片堆砌） | 仅作为时间线条目：标题、状态、摘要 |
| 工具行 | `tool.started/finished` 折叠显示，默认收起原始 JSON |
| 流式正文 | `message.delta` 打字或块追加，按 `stream_id` 归并 |

### 行为细则

1. 收到 `plan.updated` 时替换计划视图，保留用户滚动位置若可能。
2. `step.started` 将对应计划项标为进行中；`step.finished` 写入一行摘要。
3. 长工具输出只展示 `output_preview`；完整产物走 `artifacts` 链接。
4. `message.delta` 使用 `requestAnimationFrame` 或短防抖合并渲染，避免每 token 重排整个时间线。
5. 任务失败时在时间线末端展示可理解错误与「重试 / 复制诊断 ID」；诊断 ID = `task_id` + `request_id`。

### 不要做的事

- 不要用多列 KPI/统计条占据首屏研究视图
- 不要把每个工具调用做成大图卡片墙
- 不要在无事件时用假进度条骗「正在思考 99%」

真实进度以 Runtime 事件为准；可用不确定进度指示（indeterminate）表达「进行中」。

## 3. 引用（Citations）

### 信息架构

- **主栏**：报告/流式正文，引用以角标 `[1]` 或链接芯片形式内嵌
- **侧栏 / 抽屉**：引用列表（`citation.added` 增量插入）
- **详情**：标题、来源类型、片段、外链或知识库文档跳转

### 行为细则

1. 事件 `citation.added` 立即进入侧栏，即使正文尚未引用——表示证据池在增长。
2. 正文中的引用标记与侧栏双向高亮。
3. `source_type`（web / standard / patent / document / …）用克制的文字标签区分，不靠大量图标行。
4. 点击知识库来源：打开文档预览（经 Gateway），不暴露 MinIO 密钥。
5. 导出 Markdown/PDF 时角标与文末参考文献表一致（由报告 API 保证；前端只渲染）。

### 空态与质量

- 零引用且 `citation_required=true` 的终稿应显示警告条：「报告缺少引用，请重跑或人工核验」
- Reviewer 的 `review.feedback` 中 `MISSING_CITATION` 应钉在对应章节附近

## 4. 人工中断（Human Interrupt）

### 触发

后端推送 `interrupt.required`（例如计划确认、审阅门、高成本工具批准）。任务状态变为 `interrupted`。

### UI 要求

1. **明确阻塞**：主时间线上方或固定底栏显示中断条，说明 `prompt`。
2. **选项清晰**：渲染 `options[]` 为可区分的动作按钮（主操作一个，其余次要）。
3. **可补充指令**：文本框发送 `message`（映射 REST interrupt body）。
4. **提交中**：按钮 loading；成功等到 `interrupt.resolved` 或 REST 200 + 后续 `task.status`。
5. **超时**：若提供 `timeout_sec`，展示倒计时；超时策略以后端为准，前端提示「已超时，请刷新状态」。
6. **可访问**：焦点陷阱在中断面板；Esc 不默认取消任务（取消需显式 `abort`/`cancel`）。

### 与 REST 的关系

- WS 的 `interrupt_intent` 仅可作「正在输入」遥测，**不能**改变任务状态
- 真正决策：`POST /api/v1/research/tasks/{id}/interrupt`
- 主动暂停：`POST .../pause`；取消：`POST .../cancel`

### 文案语气

- 用「需要你确认」而非「Error」
- 选项动词明确：「继续专利对比」「直接生成报告」「终止任务」

## 5. 连接与恢复

| 场景 | UX |
|------|-----|
| 首次进入任务页 | 拉 REST 详情 → 连 WS → `auth` + `last_seq`（本地持久化） |
| 断线 | 非阻塞提示「实时连接已断开，重连中…」；时间线只读 |
| 重连 | 重放至 `replay_eof`，再接实时事件 |
| 令牌将过期 | 后台 refresh，避免中断条提交失败 |

`last_seq` 存 `sessionStorage` 或按 `task_id` 键的本地存储。

## 6. 动效预算（建议）

1. 新步骤出现：短促淡入/位移（~150–200ms）
2. 引用侧栏新增：列表项轻微高亮脉冲一次
3. 中断条出现：从底部或顶部滑入，并伴随焦点移动

避免：强光晕、无限弹跳、大面积视差。

## 7. 移动端

- 时间线单列；引用用底部抽屉
- 中断面板全宽，按钮纵向排列，防止误触
- 不在小屏堆叠双栏仪表盘

## 8. 验收清单（UX）

- [ ] 无 WebSocket 时仍能通过 REST 看到终态与报告
- [ ] 刷新页面不丢已完成步骤（重放或 REST 快照）
- [ ] 中断出现后无法在不知情下继续「假装完成」
- [ ] 每条引用可打开来源或片段
- [ ] 长任务 30min+ 连接可恢复
- [ ] 错误展示包含 `task_id` 便于运维

这些原则直接服务 Deep Research 产品差异化：相对「黑盒一次生成」，ResearchOS 强调可控、可引用、可打断。
